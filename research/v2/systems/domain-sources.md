# Domain sources: initial primary anchors

Access date: 2026-11-10. These are initial discovery and source snippets; no full standard, entire test suite, or system implementation has been audited.

- [NASA Systems Engineering Handbook](https://www.nasa.gov/reference/systems-engineering-handbook/): systems engineering material organized around system design, product realization and technical management. A source for thinking about lifecycle and multi-disciplinary decomposition; not a universal repository checklist.
- [NIST SP 800-160 Volume 1](https://nvlpubs.nist.gov/nistpubs/SpecialPublications/NIST.SP.800-160v1.pdf): systems security engineering integrated into systems engineering. Verify revision and full applicable requirements for a specific system.
- [W3C testing policy](https://www.w3.org/policies/testing/): specifications use tests to support interoperability and normally expect normative changes to correspond to web-platform-tests changes or a rationale. A browser needs many more forms of evidence than this test suite.
- [Android compatibility test suite overview](https://source.android.com/docs/compatibility/cts): one platform compatibility mechanism. Compatibility does not establish full OS quality or security.
- [MLIR testing guide](https://mlir.llvm.org/getting_started/TestingGuide/): examples of compiler infrastructure testing approaches. Compiler equivalence and safety still require additional analysis.
- [FIX Protocol](https://fixtrading.org/standards/fix-protocol/): trading communication standard. Message-level conformance does not establish correct exchange operations, risk controls or settlement.
- [OWASP ASVS](https://asvs.owasp.org/): web application security requirements and verification guidance. It is one security source for applicable web systems, not a whole-platform specification.
- [FAA AC 20-115D](https://www.faa.gov/airports/resources/advisory_circulars/index.cfm/go/document.information/documentNumber/20-115D): aviation software assurance guidance, scoped to its stated certification context. Its status and applicable legal force must be checked for the project and jurisdiction; the page states the advisory circular is not itself a regulation.

Further discovery leads include geospatial standards and conformance suites, multimedia codec specifications and test vectors, hardware interfaces, operating system conformance, game/graphics APIs, vulnerability-scanning protocol specifications, program analysis/reverse-engineering research, payment systems, accessibility, and live platform reliability. Do not claim these have been comprehensively examined.
