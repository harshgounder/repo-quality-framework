# Research record integrity audit

Baseline commit: `8d3a9cb` before this audit. Script: `python research/audit/check_integrity.py`. Saved output: `integrity-output.txt`, captured after AUDIT-P02 was appended to the search ledger. Independent Luna reviewer separately counted tables and inspected references; parent reran the check and corrected the reviewer's initial status grouping (109 thin, not 110: one is `searched: static source only`).

At capture: 27 campaigns, 344 queries, 133 planned cells, 161 search-ledger entries, 612 benchmark-index rows. No duplicate primary campaign/query/cell/ledger/index IDs, duplicate `(cell,query)` pairs, or duplicate `(cell,run,relationship)` triples appeared. Query-to-campaign, cell-to-campaign, cell-primary-query, cell-query-to-cell/query, cell-run-to-cell, and cell-run-to-ledger exact foreign keys had zero missing distinct values.

The earlier zero-missing conclusion did not include the compatibility `planned-cells.run_id` field. **20 cells** contain a nonblank legacy primary cell/run pair missing from `cell-runs.csv`; these use 16 distinct legacy IDs. Nineteen of the 20 cell references name run IDs absent from the join table globally; PC75 references `TEST-S01`, which exists for a different cell but has no PC75 link. Eight cell references (PC01, PC02, PC19–PC23 and PC75) match a ledger ID exactly. Twelve (PC73, PC74, PC76–PC85) do not match an exact ledger ID. All 20 lack any run-link row for their cell. These are schema/provenance discrepancies to investigate; they are not proof that the searches did not occur, because run IDs may be aliases or batch references and other join rows can exist. No IDs or statuses were silently rewritten.

Normalized statuses by prefix: 109 thin, 21 queued, two no evidence found, one searched, zero saturated. Literal statuses include explanatory prose; prefix normalization is not a finalized migration. All ten non-English-labelled query-bank records are marked planned; the separately documented Portuguese Reddit thread still exists. The 612 benchmark records are 233/379 uncanonicalized source-index rows.

C01 remains `queued` although PC01 and `first-findings.md` record a static snapshot of the pre.dev estimator. A campaign can remain queued if its broader question was not completed, but the status should explain that partial work. Do not overwrite it without reconciling the campaign's intended scope and run history.

These checks verify structure, not whether cells are well-scoped, a source supports a claim, a search really ran, a tool executes correctly, or an evaluator predicts quality. Further work: inspect each legacy run alias against original event/output, check source-register and claim-level identity, compare planned and actual queries, and produce a reproducible migration with preserved original values.

The reproducible `legacy-run-crosswalk.csv` lists each affected cell, its primary value, exact ledger match, text-search indicator, and any other run links. A substring match in the log is only a lead: e.g. `LAB-S01` occurs inside longer IDs and is not an exact ledger match.

A second Luna history reviewer found original raw calls and returned outputs bearing labels EV-S04, METHOD-S02, TEST-S02, X-THREAD-02, AX-RECENT-CODING, AX-PROBE-01, AX-SESSION-01 and LAB-S01. Their exact IDs are missing from the ledger, but the calls occurred in retained raw session events. Exact alias-to-cell and source matches remain to be established before migration. PC75 `TEST-S01` does not appear to be a self-evident match to the modal cell merely because the ID exists; review content and scope.
