# Scale-oriented discovery: first bounded tranche

The user requested thousands of candidates and examples across each relevant class, an expandable discovery process, and far broader specialist depth. This tranche starts building two source-specific queues; it does not meet the requested scale for every class, complete the wider audit, or create a validated quality framework.

| Record class | Collected | What the number actually means |
|---|---:|---|
| GitHub issue-search leads | 1,577 distinct URLs, across 1,577 returned records | Public issue metadata matching the literal bug label in 16 selected projects, pages 1–2 where page 1 filled. These are not verified failures or unique underlying mechanisms. |
| Pinned source-file leads | 8,984 file paths | 5,889 Linux device binding YAML files, 123 FFmpeg FATE makefiles, 46 ROS 2 design Markdown files, and 2,926 RTEMS specification YAML files, each with a commit and blob SHA. A file is not necessarily one requirement, test, component or design. |

The issue searches returned zero for seven projects using the literal label, plus Grafana returned seven; no conclusion follows that they have no bugs. Page two was requested for the eight full first pages and Grafana: total 770 rows; there were no cross-page duplicate issue URLs at collection time. A search result is neither a full report read nor independent confirmation. GitHub returns at most the requested page and the search results change over time; API-reported totals are not added to these counts. The four tree responses recorded `truncated=false` for their selected subtrees, but path extensions and selected subtrees exclude other files. A metadata API response does not establish source content or license suitability. Diversity is limited: both queues use GitHub, represent a small non-random selection of projects and are heavily biased toward English, open source, and recent issue updates.

See [manifest](manifest.md) for declarations, exact filters and limits; [page-one runs](run-manifest-page1.csv), [page-two runs](run-manifest-page2.csv) and [file runs](source-file-runs.csv) for UTC times, source versions and per-run counts; and the CSVs for individual URLs. The scripts are a bounded research collection record, not a robust crawler or a production-scale database. Re-running a script overwrites its respective snapshot, while upstream search results and HEAD may change; preserve or version outputs before repeating it. No upstream project code or tests were executed.

[Further source campaigns and scale accounting](next-source-campaigns.md) identify independent databases, regulatory incident records, standards/test corpora and design sources. They are routes to be examined, not completed extractions. Next: resolve alternate bug labels for zero-result projects; expand outside GitHub and English; parse source-specific units rather than treating each file as a single case; stratify and open samples of reports and file contents; link incidents, mechanisms, designs, checks, applicable contexts and counterexamples with source/version provenance; assess extraction accuracy and duplicate identities. Separately build candidate pools for measurements/estimates, roles, workflows, tools and other classes. Avoid false precision or numerical estimates unsupported by input evidence.

## Spot checks and independent review

The parent opened selected issue bodies: LLVM issue [#53493](https://github.com/llvm/llvm-project/issues/53493) reports a clang-tidy crash around a C++20 test; Zephyr [#125283](https://github.com/zephyrproject-rtos/zephyr/issues/125283) reports network bridge test failures on particular boards; ClickHouse [#92834](https://github.com/ClickHouse/ClickHouse/issues/92834) reports a logical error and describes reproduction uncertainty. These are reports, not reproduced defects. Selected file reads showed a Linux generic access-controller binding, an FFmpeg AAC makefile defining multiple targets and an RTEMS clock-rate constraint; none was executed or validated.

An independent Luna reviewer reconciled each run's counts with the CSVs and checked three issue metadata records and three commit-pinned file records against the source API. They found 8,968 distinct blob hashes among 8,984 paths; equal content can occur at multiple paths, so even file content and path totals are distinct. They verified ROS 2, RTEMS and FFmpeg samples; their Linux web fetch timed out, while the parent's Linux source read succeeded through the API. These selected checks do not verify the rest of the records or the truth of reported defects.
