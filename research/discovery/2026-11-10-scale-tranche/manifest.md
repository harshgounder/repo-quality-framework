# Large-scale discovery tranche — declared before collection

Date: 2026-11-10. Aim: establish a reproducible, materially larger pool of *potential* defect and failure cases spanning different technology domains. The user's requested scale is thousands of cases, designs, components, estimates and other elements in each relevant class over continued research; this first tranche addresses only one class and does not satisfy that broader target.

Before retrieval we selected the following public GitHub projects for contrasting technical domains, not as a representative sample of the world: llvm/llvm-project (compiler), rust-lang/rust (compiler/language), godotengine/godot (game engine), tensorflow/tensorflow (machine learning), zephyrproject-rtos/zephyr (embedded/RTOS), bitcoin/bitcoin (cryptocurrency), openssl/openssl (cryptography), opencv/opencv (computer vision), OSGeo/gdal (geospatial), kubernetes/kubernetes (orchestration), NixOS/nixpkgs (packaging), eclipse-sumo/sumo (traffic simulation), blender/blender (3D), grafana/grafana (observability), ClickHouse/ClickHouse (database), and apache/arrow (data interchange).

For each project execute GitHub's issue search API with exact query `repo:OWNER/REPO is:issue label:bug`, `sort=updated`, `order=desc`, `per_page=100`, `page=1`. Retain issue title, URL, number, creation/update dates, state and labels, plus run metadata and API-reported total. Search results are issue metadata, not independent evidence that a bug exists, nor a random sample or the whole source. GitHub's search index, label conventions, source accessibility, sort order, page cap and English/GitHub skew bias this tranche. Labels, body and patches require further reading before a case or mechanism is verified. Empty/inaccessible results and request errors will be recorded; do not replace them with invented candidates.

Deduplicate by canonical issue URL within this batch, retaining separate source/project metadata. Do not equate counts with unique underlying bugs, verified mechanisms or coverage. Record retrieval time, observed totals and any incomplete-results flag. Never convert these issues directly into mandatory checks. Subsequent tranches must cover other platforms and source types, non-English communities, individual mechanisms, system designs, measurement/estimations and the other requested element classes.

## Second page, declared after page-one results and before page-two retrieval

No label substitution or inferred result is performed. Alternative project-specific labels remain an explicit follow-up.

## Source-file inventory, declared before retrieval

Collect a separate set of version-pinned repository tree entries under Linux `Documentation/devicetree/bindings` (`.yaml`/`.yml`), FFmpeg `tests/fate` (`.mak`), ROS 2 `articles` (`.md`), and RTEMS central `spec` (`.yml`/`.yaml`). Resolve each default HEAD to a commit, walk the exact subtree, and request its recursive tree. Retain each matching blob path, URL pinned to the commit and blob SHA, plus response truncation and errors. A file is a candidate source document, not an independently reviewed design, component, test, requirement, individual YAML item or verified fact. The collection may be incomplete if the API truncates or a path is invalid; count only actual retained entries and preserve failures.
