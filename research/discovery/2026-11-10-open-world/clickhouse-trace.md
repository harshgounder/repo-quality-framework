# Example: issue, competing patches and an actual merged fix

This one example illustrates the depth required, not the boundary of the project. On 2026-11-10 the parent queried the public GitHub issue and timeline, then the two cross-referenced pull requests and their file lists. The target software and tests were not run.

- **Report:** [ClickHouse issue #92834](https://github.com/ClickHouse/ClickHouse/issues/92834) reported a logical error involving a min/max time index. The reporter described reproduction uncertainty. One error string alone does not establish a unique cause.
- **Competing proposal:** [PR #93111](https://github.com/ClickHouse/ClickHouse/pull/93111) proposed handling null or incompatible bounds. Its current record was closed **without merge**. It identifies limitations involving stale slots and compatible underlying storage types. Its existence is not evidence it fixed the issue.
- **Merged change:** [PR #120862](https://github.com/ClickHouse/ClickHouse/pull/120862) explicitly closes the issue and was merged 2026-09-22. Its description identifies reordering of a partition-key column as changing positional min/max index assumptions, with effects including incorrect query pruning; it describes ordering index columns by key names and addressing a second projection derivation. This is the PR author's explanation, not an independently reproduced causal finding.
- **Tests and remaining limitation:** the PR file list includes a new SQL regression test and reference output, plus changes in two implementation files. The PR description says already-written mixed bounds can persist and discusses different recovery options. The PR reports a version and compatibility checks; neither was independently verified here. No test was executed, and source-linked closure alone cannot prove every historical manifestation of the issue was fixed.
- **Candidate research directions:** check state/index identity when metadata order changes, consistency between independent derived structures, regression matrices covering old/new data and schema transitions, silent wrong-result oracles as well as crash checks, and recoverability of persisted corruption. Applicability depends on the actual storage design and evidence; no mandatory general gate is established.

**Evidence limit:** only selected issue body, timeline events, PR descriptions and file listings were inspected. The full diff, individual test assertions, CI records, release contents, alternative explanations and reproduction remain to be examined. The issue history contains additional cross-references and commits; the selected two PRs do not constitute a complete event-history audit.
