# Related projects and reusable research — 2026-11-11

This initial discovery tranche compares different *parts* of our objective. A project's own description is not independent proof of quality, present availability, dataset accuracy, reproducibility, rights or fitness for use. Counts below are source-reported where given and depend on version. Before copying code or data, verify licenses, component and source-project terms, attribution, compatibility, data access restrictions and privacy. Project links are discovery and inspection routes, not endorsements or exhaustive coverage. Agents inspected primary project pages/papers; the parent additionally checked selected GitHub metadata and the IDB, failure-analysis and Defects4J primary descriptions. No third-party code or dataset was imported or executed.

## Synthesis and next checks

There are strong partial overlaps: source-linked incidents, reproducible bug/test corpora, architecture rules, professional guidance and quality assessment systems all exist. The search so far does **not** establish that no one has combined them, nor that the newest/smallest projects work as claimed. The promising immediate investigation is to inspect actual schemas and licenses of IDB and selected reproducible-bug corpora; compare the implementation and source evidence behind Engineering Radar, Sensei and Repo Health; discover equivalent work across non-English and non-GitHub communities and other physical, scientific, security, organizational and human-workflow domains; resolve duplicated underlying cases across datasets; and compare them to the wider source/claim/run model. Keep the user's thousands-per-class ambition, with separate counts for discovery, identity, source review and validation. No third-party implementation or dataset should be imported merely because its name or README sounds aligned.
